    Development

    Environment and configuration

    uv sync --locked --dev
uv run pytest tests

    This repository contains the node asset libraries and the installable omoonodes package. src/omoonodes/ provides the omoonodes command, configured by the calling project's pyproject.toml:

    [tool.omoonodes]
targets = ["b45", "b52"]

    Defaults: Python 3.11 / bpy 4.5.14 for b45; Python 3.13 / bpy 5.2.2 for b52. uv prepares native target environments in .cache/nodes/. Each target builds, exports, saves, and checks its own files. tool.omoonodes.versions overrides exact bpy versions. Input files and their dependencies must match the target major/minor version.

    Commands show ... while working, ✔ on completion, and output directories at the end. Blender Info, Warning, read-path messages, and leak statistics on successful exit are hidden; other Error messages or unsuccessful exits stop the command.

    Node development

    nodes/<library>/ contains Python, resources, catalogs, and collection.json describing files and dependencies. Sources use nodebpy-style node classes, Socket expressions, and >> links, imported from omoonodes. dev and build arrange nodes automatically; sources contain no node positions or layout options. Cross-file references import node classes through nodes.<library>.<source>.... The CLI loads sources for the selected target and uses relative links declared in collection.json. Shared implementations use .py; b52-specific implementations use .b52.py. Related libraries share one target parent directory.

    nodes/O/ contains the O asset library. Three O_Base_*.blend files and O_Extra.blend hold compositing, geometry, shader, and effects assets. Shared nodes are linked from their owning files. Local publishing saves linked files before the files that reference them. Blender's Add menu shows catalogs such as O Deform directly.

    # Import assets and dependencies into a new source directory
uv run omoonodes dump path/to/O_Library.blend -o nodes/O_Library

# Build and overwrite development libraries
uv run omoonodes dev nodes/O -o workspaces

# Export development libraries, overwriting Python sources and resources
uv run omoonodes dev nodes/O -s workspaces

# Build the local library
uv run omoonodes build nodes/O --target b45 -o contents

# Remote libraries with dependencies, native listings, metadata, thumbnails, and SHA-256
uv run omoonodes build nodes/O --target b52 --remote -o dist

    People edit development libraries in Blender; AI edits sources directly. The operator chooses the overwrite direction. Export also removes sources for deleted assets. dev defaults to the lowest target; build defaults to all targets. Sync selects the unique workspace target, requiring --target when several exist. Omitted sources use tool.omoonodes.source, defaulting to nodes. Default outputs are workspaces/<target>/<library>/ and dist/<target>/<library>/. Builds use temporary directories, save and reload in the target Blender, then replace outputs. CI archives the results for release.

    Publishing the Python package

    .github/workflows/test.yml runs tests and builds packages on pushes to main and pull requests targeting main, then checks both the wheel and sdist by building, exporting, and rebuilding a minimal node.

    .github/workflows/publish.yml runs on cli-v* tags, tests the source, and builds the sdist and wheel. Each package is installed and checked by building, exporting, and rebuilding a minimal node in a temporary project before publishing omoonodes through PyPI Trusted Publishing. The package version comes from pyproject.toml.

    Before the first release, create a GitHub environment named pypi and add a pending publisher at PyPI Publishing with project omoonodes, owner OmooLab, repository OmooNodes, workflow publish.yml, and environment pypi. The first successful upload creates the PyPI project; no API token is needed.

    Commit the version and lockfile, then push the matching tag, for example:

    git tag cli-v0.1.0
git push github cli-v0.1.0

    Publishing the node asset library

    Annotated nodes-v* tags trigger .github/workflows/release.yml. The workflow builds the b45 local and b52 remote libraries in parallel, then publishes both archives in one GitHub Release. The tag annotation supplies the release notes.

    git tag -a --cleanup=verbatim -F path/to/release-notes.md nodes-v0.2.0
git push github nodes-v0.2.0

    Library versions come from the tag. Archives named like OmooNodes.v0.2.0.b45.zip extract to O/. The b52 remote library is served at https://assets.omoolab.xyz/o/.

    Documentation

    uv run python -m tools.docs test    # Strict build in a temporary directory
uv run python -m tools.docs dev     # Local preview
uv run python -m tools.docs build  # Build major.minor.x and commit to local gh-pages
uv run python -m tools.docs deploy # Push to the github remote

    Node documentation lives in docs/nodes/; the machine reference is .agents/skills/use-omoo-nodes/references/node-catalog.json.

    Source definitions import omoonodes; see src/omoonodes/README.md for the small Python API. Unchanged content is not rewritten. Shared edits must build in every inheriting target before sources are replaced. Existing .b52.py implementations remain target-specific; DISABLED = True disables an asset for that target. Structural checks do not establish effect equivalence.
